# 自动拒绝隐私提示修正版 · 3.0.0-preview3

## 本轮变化

- 自动点击中央提示的 `Do not consent`，以及底部 Cookie 条的“不同意并继续”。这两种提示同时出现时分别拒绝，绝不点击“可选同意”或“全部同意”。
- 修复关闭检测：不再把持续存在的工作台网页外层固定容器当作未关闭的弹窗。仍会检查真正的弹窗和专用遮罩；拒绝后只隐藏 iframe、未移除 iframe 的情况也能识别。
- 按钮暂时被遮挡、不可用或正在动画时重新查询并重试，每个提示最多等待 15 秒。如果首次点击发生在网站事件就绪之前，等待后重试同一个明确拒绝按钮一次；不重复点击已被网站标记为忙碌或禁用的按钮。绑定实际按钮元素，避免前一个弹窗消失后把关闭检测误指向另一个按钮。
- 如果拒绝按钮被窄截图窗口裁到屏幕外，临时加宽浏览器以正常点击，之后恢复原截图宽度，包括失败情况。不强行点击遮挡后的元素。
- 使用原来的 `data/browser` 持久化浏览器，保存网站实际写入的拒绝偏好。网站可能因过期、政策变更等再次询问，这时重新自动拒绝；不伪造网站 Cookie，不承诺网站永久不询问。请保留整个 `data`。
- 修复重启后“请先打开本机 WebUI 首页”：首页禁止缓存，Windows/Mac 启动器打开带新参数的首页，替换旧会话。

评论加载、分段译文、`/e`、补充新评论、最新成功版本覆盖、水印和四个必填页面选择器保持上一版的用法。没有增加依赖。

## 已安装项目如何升级

Windows 使用 Python 3.14，Mac 使用 Python 3.13（Intel Mac 适用）。

1. 关闭程序及工作台打开的浏览器，备份 `data`。
2. 将下载包解压到另一个文件夹，核对 `VERSION` 为 `3.0.0-preview3`。
3. 把新版 `weverse_bot`、`static`、`docs` 完整替换到原项目；替换 `run.py`、`VERSION`、`requirements.txt` 和自己系统的两个启动文件。
4. 保留原项目的 `data` 与 `.venv`，无需首次安装。
5. 运行新版“启动工作台”。使用启动器自动打开的首页，原有设置无需重填。不要继续使用之前的旧标签页。
6. 在首页用原来失败的 Weverse 网址读取测试。已知两种隐私提示应自动拒绝，无需每天手动选择。

如果网站产生新的提示样式或拒绝后仍保留遮罩，程序会停止截图。新版错误会区分“拒绝按钮点击失败”“已点击但弹窗或遮罩未关闭”“未找到明确拒绝按钮”；可提供工作台浏览器里的提示截图和拒绝按钮 outerHTML 继续适配。

## 验证范围

新增回归覆盖持续存在的网页固定外层、无 role 的提示、超过 5 秒的关闭动画、临时覆盖和延迟可用按钮、隐藏但未移除的 iframe、iframe 与底部条同时出现、多个同名按钮、首次点击早于网站事件就绪、裁到屏幕外的按钮，以及残留专用遮罩仍然停止截图。已有拒绝偏好跨持久化浏览器重启、评论读取和译制测试继续执行。

另用真实本机 HTTP 服务与同一个 Chromium 标签页测试两次程序启动：第二次以同一首页网址导航，不添加参数也能拿到新会话并保存设置。启动器参数用于避免已经安装的老版本缓存首次升级时继续生效。

界面冒烟测试首次与多套 Chromium 并行时，原有 5 秒译图等待超时；独立重跑通过，未放宽断言。译制界面和同一标签页的服务重启测试也已通过。

102 项自动测试全部通过。两套原有界面流程与会话重启验证均通过。实际结果分别保存在 `preview3-test-results.txt`、`preview3-ui-results.txt`、`preview3-translation-ui-results.txt` 和 `preview3-session-ui-results.txt`。

测试在 Linux Chromium 和受控网页运行，网站偏好保留由模拟网站实际写入 Cookie 后验证。没有你的真实 Weverse 会话，也没有在 Windows/Mac 本机执行安装器；请用原失败网址本机验收。两平台共用程序源代码，独立启动文件，包内不包含登录、QQ Token、数据库或图片。
