# 后续更新需求记录

本文件记录 v2 交付后的讨论。标为“待更新”的内容尚未进入程序，不能视为已实现。

## 截图修正：本次处理

- 用真实作者区域保留头像、艺人名称和身份标识，不能只截正文和配图。
- 移除截图中的 Weverse / PLAVE 站点导航、菜单和底部登录邀请悬浮框。
- 截图前自动点击官方 `Do not consent` 拒绝按钮；支持同意弹窗所在 iframe。
- 拒绝后的偏好由 Bot 的持久化 Chromium 浏览器保存；弹窗再次出现时重新处理。
- 不用 CSS 隐藏同意弹窗代替拒绝；无法拒绝或作者区域不可见时停止截图并说明原因。
- 公开动态可在未登录状态读取。需要账号权限的内容仍按网站要求登录。
- 真实网页仍需用户在本机验收。当前选择器仅根据所提供的 YEJUN 单段正文页面校准。

## 动态、编号与分类：待更新

- 产品中的“档案”概念全部替换为“动态”。
- 绑定 Weverse 社区，抓取艺人动态和艺人评论，按发布时间从先到后累计。
- 编号显示为 `0001`～`9999`，与发布时间相关；截图、烤制及分类变化不改变编号。
- `/待处理`：未截图、未烤制。
- `/待烤制`：已截图、未完成烤制。
- `/仓库`：汇总上述两类未完成动态。
- 烤制完成后退出仓库；动态编号、原图和成图保留。
- `/清除待处理`、`/清除待烤制`、`/清除仓库`：分别永久删除对应范围的数据和图片。
- `/清除仓库` 的范围不包含已经完成并退出仓库的动态。
- 分类指令和清除指令采用这次确定的 `/` 前缀；其他短指令沿用此前规则。
- 待确认：补抓更早动态时怎样兼顾时间顺序与已有编号；超过 9999 的处理规则。

## 文字水印与翻译名称：待更新

- 去除 PNG Logo、水印图片上传及相关指令，只保留文字水印。
- 整张最终图片正中心放一处文字水印，固定格式为
  `@Plave_PixelDiary 翻译：绑定的名称`。
- 透明程度暂按用户提出的约 20% 记录，实际深浅、字号和布局以例图为准。
- 授权时名称必填，例如 `设置权限 -l 2 名字：小鱼 @群成员`。
- 保存 QQ 号、授权等级和翻译名称；每次烤制由发起人的 QQ 号找到绑定名称。
- QQ 群昵称变化不自动改变绑定的翻译名称；主人也需要配置翻译名称。
- 主人及 level 3 可授权他人，数字越大权限越高，保留权限继承规则。
- 待确认：删除 Logo 功能并固定文字水印后，level 1 可以修改的具体范围。

## 工作台与模拟群聊：待更新

- 真实 QQ 群承担日常截图、烤制、列表、清除及权限操作。
- 工作台提供模拟群聊入口：用户发指令/网址/译文，程序以机器人角色回复文字和图片。
- 默认以主人身份模拟，可切换 level 3、level 2、level 1 和无权限成员验证权限。
- 模拟与真实群使用同一套指令逻辑；模拟数据单独保存，避免测试清除真实动态。
- 保留管理设置、QQ 连接、Weverse 登录、抓取和运行状态入口。

## 烤制版式：待更新、继续校准

- 用户主要提供网址和人工译文，机器人自动读取网页；上传截图用于样式核对和备用。
- 参考例图：保留原文，白底追加中文，译文位于原文之后、配图之前。
- 根据译文实际长度扩展高度，配图和下方信息整体下移，保留图片比例。
- 移除旧版带标题的绿色翻译框和底部整理栏。
- 艺人评论的译文应与对应原文配对，不混入粉丝评论。
- 已讨论三种方案：截图扩图、数据加固定模板、网页插入译文后截图。
  固定模板是针对排版稳定性的建议，最终方案及细节尚待样张确认。
- 参考 Bot 示例中的 `/e`、`/u` 用途尚未获得源码确认，不视为本项目已确定的新指令。

## 系统与 Python 版本

- Mac 以 Python 3.13 为安装、说明和排错基准。
- Windows 以 Python 3.14 为基准；沿用旧版程序的两个 `.bat` 已单独提供。
- 统一源码，分别提供 Mac / Windows 启动文件及相应安装说明、下载包。
- Windows 安装脚本已经修正为优先检查 3.14，并验证实际解释器与虚拟环境。
