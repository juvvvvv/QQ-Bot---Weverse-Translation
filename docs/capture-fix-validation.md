# 截图遮挡修正与验证（2026-10-07）

## 本次改动

真实网页抓取成功后，站点固定导航、登录邀请和隐私同意框仍会覆盖卡片截图。
本次修正只处理截图准备流程，不实现后续动态分类、翻译名称、水印和模拟群聊改版。
完整待更新清单见 [next-version-requirements.md](next-version-requirements.md)。

- 截图前自动点击明确的 `Do not consent` 等拒绝按钮，包含 iframe 内的按钮。
- 等待拒绝按钮、同意对话框及所在固定遮罩消失；无法处理时停止截图并说明原因。
- 由持久化 Chromium 保存网站写入的拒绝偏好，不伪造同意 Cookie 或接受可选同意。
- 仅对截图页面隐藏已识别的站点导航和底部登录邀请，不隐藏艺人作者区域。
- 响应式布局隐藏作者头部时恢复该头部；确认作者名称和已识别的头像区域可见。
- 页面显示作者区域不完整时停止，不把缺作者的图片保存为成功结果。
- 公开动态抓取成功不再被描述成“已登录”。

## 用户本机更新方式

1. 停止现有工作台：在其终端窗口按 Ctrl+C。
2. 下载本次完整源码并解压到另一个文件夹。
3. 将新包的 `weverse_bot` 文件夹复制到原项目内，合并并替换同名文件。
   本次实际更新 `capture.py`、新增 `page_cleanup.py`，必须一起更新。
4. 保留原项目的 `data` 和 `.venv` 文件夹。依赖和数据库结构没有改变，无需重新安装。
5. Windows 以 Python 3.14 为基准，使用原项目的 `启动工作台.bat` 重新启动。
   Mac 以 Python 3.13 为基准，使用 `启动工作台.command`。
6. 浏览器刷新工作台，再用同一条真实网址截图；已生成的旧截图不会自动重做。

仍使用先前校准的四个必填选择器，初次复测先留空评论选择器：

| 设置项 | 样本中的值 |
| --- | --- |
| 帖子卡片 | `.community-artist-postId-_-main` |
| 正文文字 | `.WeverseViewer > p.p` |
| 作者 | `.avatar-decorator-_-title` |
| 艺人标识 | `svg g[id="24/em/ic_officialbadge_special_medium"]` |

这些值只在所提供的单段正文样本中核对过，不等于全部动态类型已经适配。

## 云端测试

Linux，Python 3.12，预装 Chromium；真实 Weverse 访问仍受云端代理 403 限制。

```text
WEVERSE_BROWSER_EXECUTABLE=/usr/bin/chromium .venv/bin/python -m unittest discover -s tests -v
Ran 39 tests in 40.183s
OK
```

39 项通过、无失败或跳过，原始记录见 [capture-fix-test-results.txt](capture-fix-test-results.txt)。

新增 8 项真实浏览器模拟测试覆盖：

- 自动拒绝同意，并验证完整截图像素中有头像、无固定导航及底部登录提示。
- iframe 中的拒绝按钮，以及拒绝后 iframe 自身关闭。
- 只有接受按钮时停止，不点击接受、不隐藏询问、不保存错误截图。
- 延迟出现的询问。
- 拒绝按钮消失但遮罩残留时停止截图。
- 隐藏的作者名称停止截图。
- 已识别作者头部缺头像时停止截图。
- 拒绝偏好在持久化浏览器关闭和重新打开后保留。

## 待本机验收

测试中的页面、图像和同意框是受控模拟，不是真实 Weverse 的现场截图。
需要用户在 Windows / Mac 用原网址复测，确认作者、头像、正文和配图完整，
没有 consent 询问、站点菜单或登录邀请遮挡。
如果拒绝按钮结构不同，提供工作台 Chromium 中该按钮的 outerHTML；
如果作者范围仍不正确，提供同一窗口同一动态的已加载 root 元素，而不是初始网页源码。
