# v3 评论译制试用版：更新和测试

这一轮实现艺人评论捕获和排序、楼中楼样式、统一译文输入、`+` 分段、`/e` 逐段表情引用、补充新评论、最新成功版本覆盖，以及最后一步底部文字水印。Mac 使用 Python 3.13，Windows 使用 Python 3.14，源代码一致。

## 更新已经安装的工作台

1. 关闭工作台、终端和工作台打开的 Weverse 浏览器。
2. 备份旧项目的 `data` 文件夹。
3. 解压对应系统的 ZIP。把其中 `weverse_bot`、`static`、`docs` 完整替换进旧项目，同时替换 `run.py`、`requirements.txt` 和对应系统的两个启动文件。
4. **保留原来的 `data` 和 `.venv`**。本轮依赖没变化，正常安装无需重装。
5. 运行对应“启动工作台”文件；说明书在 `docs/manual.html`。
6. Mac 提示没有执行权限：终端输入 `chmod +x `（末尾一个空格），拖入两个 `.command` 文件，回车；也可输入 `bash ` 后拖入启动文件执行。

首次安装先运行“首次安装”文件。Mac 优先寻找 Python 3.13，避免选中旧 Anaconda；Windows 优先使用 Python 3.14。Mac ZIP 启动文件带可执行权限，解压工具仍可能改变权限。

## 建议这次依次测试

1. 保留之前成功的四个正文选择器，勾选“自动读取艺人评论”，保存。
2. 读取 `https://weverse.io/plave/artist/3-241901329`。如果网页仍显示 14，应有正文 + 14 条艺人评论，共 15 个版块；计数是读取时快照，不固定写成 14。
3. 核对头像、作者、时间、评论原文、表情和链接；普通评论有框，楼中楼有缩进和细线。相同分钟反转网站原始叠放顺序。
4. 查看每段“本段表情顺序”。在唯一译文框填 15 段，段间用单独一行 `+`。引用表情用 `/e`，连续两个用 `/e/e`，未引用的不会追加。
5. 生成后核对每段“原文 → 中文译文”，正文配图在正文译文下面，评论在配图下面；检查宽度、框线和底部留白。
6. 水印面板选择 8（中下），调整文字和大小，保存后再次完整烤制。旧配置不会强制改位置。
7. 修正错字：修改完整模式已填译文，重新生成。只保存最新成功版本；网页读取或段数错误不会覆盖它。
8. 新评论出现后重新读取**相同链接并选择同一 QQ 群**，切换“补充新评论”，只填提示数量的新增段。QQ 中则在译文开头单独写一行 `+`。

原文变动、已存档评论缺失会阻止补充，请核对后使用完整模式。存档保存的是 `/e` 替换后的实际表情，后续引用不会再次错位。

- 真实浏览器验证统一输入、完整烤制、`/e`、补充、覆盖和错误保留，未发生浏览器脚本错误。日志：`v3-interaction-results.txt`。
- 既有管理界面、文字水印预览与保存、清空、窄屏和 13 节 HTML 说明书回归：`v3-ui-results.txt`。
- [14 条评论离线样图](v3-native-comments.png) 使用你提供的 DOM、测试 CSS 和替代头像，用于核对样式和顺序，**不是实时 Weverse 截图**。
- [统一输入与存档界面](v3-unified-input.png) 使用明确标注的离线数据。

测试环境为 Linux + Python 3.12 + Chromium；启动文件做静态检查，未声称在 Windows/macOS 上实际安装。你本机已成功的安装可继续使用。

提供的 HTML 没有父评论编号，能确定楼中楼样式，却无法唯一确定回复哪条同名作者评论。优先读明确父 ID；缺失时按时间、缩进呈现并提示，不凭 @名字猜测。真实接口结构仍需本机验证。

当前最多 200 条评论。精确计数不匹配会停止；未知计数仅列已读内容并提示人工核对。尚不保证全部虚拟滚动或分页变体。

已知同意弹窗继续明确选择“不同意”，重复检查。未知底部收集提示按约定等待复现；再次出现时提供 Bot 浏览器中该提示的 outerHTML。

## 下载包
